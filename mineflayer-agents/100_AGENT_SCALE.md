# 100人の人物設定と負荷試験 (2026-11-10)

## 結論

- `configs/survival_100.json` に、10〜87歳の100人を作った。乱数の種は `20261110` で固定し、再生成できる。
- 年齢層は子供21人・若者23人・大人30人・老人26人。各層を最低20人にし、残り20人を日本の人口比で分けた。
- 性格と欲求は年齢・性別・Big Five に基づく。職業や役割は与えていない。
- 100人・20プロセスの試験は2回とも100人が接続し、APIエラーは0だったが、切断は2件と14件だった。厳密な合格条件「切断0」は未達。
- 主な律速は16論理CPUに対する20個の Node プロセスと、各プレイヤー周辺のチャンクを処理する Fabric サーバー。次の検証は10プロセスと軽量化したサーバー設定で行う。

## 人物モデル

### 年齢と性別

総務省統計局「人口推計 (2024年10月1日現在)」第1表の各歳・男女別人口を使う。

- 子供: 10〜14歳。性格研究の対象が10歳以上なので、10歳未満は推測せず入れない。
- 若者: 15〜29歳。
- 大人: 30〜64歳。
- 老人: 65〜89歳。90歳以上は性格データからの外挿が長くなるため入れない。
- 各層を最低20人にし、残りを人口比で配分する。層の中の年齢と性別は人口に比例させる。

### 性格

- 25〜79歳: 川本ら (2015) の日本人4,588人の TIPI-J、年代×性別の平均・標準偏差。
- 10〜24歳: 25歳の日本人基準に Soto ら (2011) の年齢差を加える。
- 個人差: 川本らの特性間相関を持つ標準正規分布から生成する。
- Big Five から既存の `bravery`・`empathy`・`obedience`・`greed`・`sociability` と好奇心へ写す。写し方と出典は `tools/gen_personas.js` の冒頭に記録した。

### 年齢による欲求

根拠がある差だけを入れた。主なものは、推奨睡眠時間、若者の夜型、高齢者の空腹感の弱さ、子供の夜への怖さ、高齢者が親しい少数の相手を選ぶ傾向、青年期の他人からの評価への敏感さ。移動速度や体力など、Minecraft の身体能力は変えていない。

### 名前

明治安田生命の生まれ年別名前ベスト10から、生まれ年に近い名前を全員へ重複なく割り当てた。Minecraft名は英字3〜16文字で、先頭部分も重ならない。

## 実測

同じ `survival_100.json` を使い、1プロセス5人で実行した。

| 実行 | 人数 / プロセス | 実行時間 | 切断 | Jev / LLMエラー | 2B p50 / p95 | 費用 |
| --- | --- | --- | --- | --- | --- | --- |
| `2026-11-10T04-19-31` | 100 / 20 | 8.91分 | 2 | 0 / 0 | 2.72s / 8.14s | $2.19 |
| `2026-11-10T04-29-08` | 100 / 20 | 8.88分 | 14 | 0 / 0 | 2.51s / 7.27s | $1.47 |
| `2026-11-10T04-38-24` | 50 / 10 | 7.63分 | 0 | 0 / 0 | 2.28s / 6.55s | $0.67 |

100人の1回目はサーバーが最大約25秒遅れ、timeout 1件とチャットの spam kick 1件が出た。2回目は約13秒遅れ、14人が同時期に timeout した。50人・10プロセスでは切断0だった。20プロセスは各プロセスがCPUの約60〜75%を使い、Nodeだけで12〜15コア相当になるため、16論理CPUの実験機ではサーバーの余裕がない。

年齢層別の集計も動作した。1回目の100人試験では、1人あたり31〜34判断、成功率74〜83%で、子供・若者・大人・老人の行動、ゴール、欲求、発言を別々に集計できた。

## 100人用のサーバー設定

- `max-players=120`: 観察者を含めて100人を収容する。
- `gamerule maxEntityCramming 0`: `spawnRadius 0` の同一地点出現による圧死だけを止める。
- `view-distance=5`: 送るチャンクを減らす。プレイヤー追跡距離は64mで、会話範囲48mを保つ。
- `simulation-distance=4`: tick対象チャンクを減らす。
- `network-compression-threshold=-1`: 同一マシンの通信なので圧縮CPUを使わない。

## 次の合格試験

```bash
bash mineflayer-agents/server-fabric/first_setting_world.sh morning
node mineflayer-agents/run.js --config mineflayer-agents/configs/survival_100.json \
  --agents 100 --procs 10 --minutes 10 --stagger-ms 1500
node mineflayer-agents/tools/check_scale_run.js mineflayer-agents/runs/<時刻> \
  --agents 100 --max-disconnects 0 --max-api-errors 0 --max-loop-lag-ms 10000 --min-minutes 5
```

合格条件は、100人全員の結果があり、切断0、Jev/LLMエラー0、各プロセスのイベントループ p99 最大が10秒以下であること。失敗した場合は、人数を減らすのではなく、まず `--procs 8` と `--procs 12` を比較する。100人を長時間動かす費用は、約9分の実測で $1.5〜2.2 だった。
