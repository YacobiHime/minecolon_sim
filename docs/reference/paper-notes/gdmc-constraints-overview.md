# GDMC の生成器で使われている制約のまとめ（論文①〜③と大会ページから）

- 作成: 2026-10-06（ユーザーの質問「どのような制約がされているか」への回答）
- もとにした資料: 論文②（`gdmc-first-year-2020.md`）、論文③（`gdmc-impressions-2022.md`）、GDMC の2020年・2023年の大会ページ、Niels-NTG の2023年の作品「Field Lab Gamma」の GitHub の README（https://github.com/Niels-NTG/GDMC2023）。
- 論文④以降を読んだら追記する。

## 1. コンペのルールとしての制約（外側の制約）

| 制約 | 内容 | 出典 |
| --- | --- | --- |
| 見たことのない地図 | 参加者は評価用の地図を事前に知らない | 論文①② |
| 建設範囲 | 3次元の範囲（バウンディングボックス）が与えられ、その中に生成する。HTTP 版では `/setbuildarea` で設定 | 評価ページ、Field Lab Gamma の README |
| 地図の大きさ | 多くは256×256程度。1000×1000の年もある（2023年の既存の集落の地図など） | 評価ページ、2023年の審査員向け説明書 |
| 計算時間 | 2018年は256×256の地図で10分程度。現在の制限は未確認 | 論文① |
| バージョン | 年ごとに固定（2023年は1.19.2、2024年は1.20.2、2026年は1.21.11） | 大会ページ |

## 2. 生成器の中の制約

制約は大きく2種類に分けられる。

- **ハード制約**: 守らなければならない条件。破る候補は捨てる。
- **ソフト制約**: 点数（評価関数）やコストとして扱う条件。よりよい候補を選ぶのに使う。

### 2.1 移動（身体性）の制約: ハード制約として使われることが多い

| 作品 | 制約 | 出典 |
| --- | --- | --- |
| 2018年1位（Skwarski） | 道を A\* 探索で引くとき、1ブロックより高い段差は通れないとみなす。丘を斜めに横切らない | 論文② 5.1節 |
| 2018年3位（Brightmoore） | 高さマップで、隣との高さの差が2ブロックを超える所を「縁」とし、通れない急斜面とみなす。縁を越えずに行ける範囲を1つの区画にする | 論文② 5.2節 |

- 論文③では、通れない段差や高低差が残ることが、くり返し問題として指摘されている（B.3、B.12）。

### 2.2 配置の良さ（ソフト制約・評価関数）

| 作品 | 制約・評価 | 出典 |
| --- | --- | --- |
| 2018年1位（Skwarski） | 候補地を5,000か所ランダムに選び、3つの基準で評価して最良の場所に置く: ①標高（周りが平らか）、②配置（その種類の建物が既存の建物と合うか、ゆるい制約）、③距離（既存の建物に近いか）。広場は周りに家があることを好み、畑は既存の建物に沿う | 論文② 5.1節 |
| 2018年2位（Fritsch） | 区画ごとに建物の種類を「適合度」で決める。家の適合度は、他の区画に対する中心性と、道に面しているか | 論文② 5.4節 |
| 2023年3位（Niels-NTG、Field Lab Gamma） | モンテカルロ木探索（MCTS）で、手作りの建物（NBT ファイル）を1つずつ置いていく。置く行動ごとにコストを計算し、コストに応じた確率で行動を選ぶ。地面から高い所に建てると支柱が必要になりコストが上がるので、選ばれにくい。コストが負の行動は候補から外す。報酬は「目標の状態にどれだけ近いか」（デバッグ用の例では、ある地点までの距離） | GitHub の README |

### 2.3 地形を平らにする／しない

- 2018年4位（Ye, Cao）は、範囲全体を平らにならしてから区画に分けた。地形の制約を受けない代わりに、適応の点数はほぼ0点だった（論文② 5.3節）。
- 論文③で Brightmoore は、平らにならす方法は「都市」、地形をその場で活かす方法は「村」に感じられると述べている（B.8）。

### 2.4 材料・環境の制約

- 2018年2位（Fritsch）: 地図の全ブロックを数え、多い木材・石材を建材にする。バイオームから平均気温を計算し、水と肥えた土地の有無から作物を選ぶ（論文② 5.4節）。
- 2018年1位: 使える木の種類を検出して建材にする（論文② 5.1節）。

### 2.5 水に関する制約

| 作品 | 水の扱い | 出典 |
| --- | --- | --- |
| 2018年の作品 | 水の上に建物を置いてしまう作品や、水に向かって開くドアがあった。水を避けて置いた作品でも、渡れない川で集落が分断された | 論文② 6.2節 |
| 2020年 University of Tsukuba | 経路探索が水の上を通れるように、特別な構造物として橋を作る | 2020年の大会ページ |
| 2020年（作品名は未確認） | ヴェネツィアのように水の上に家を建てた作品があり、審査員に高く評価された | 論文③ B.12 |
| 2023年 MGAIA（ライデン大学）「Collapsing Water Waves」 | 水のシミュレーションを使って、建物どうしをつなぐ道を作る（具体的な方法は大会ページに書かれておらず未確認） | 2023年の大会ページ |

### 2.6 道路網の作り方

- A\* 探索（2018年1位・4位、2020年 Tsukuba）
- 最小全域木（論文③ B.10 で Aranha が教育の例として挙げている）
- アリコロニー最適化（2023年7位の Deinböck、論文⑦）
- 区画を二等分した真ん中を道にする（2018年2位）
- 大規模な道路網（2023年の ReXenGen-2023 が革新賞。方法は未確認）

### 2.7 論文④（van der Staaij ほか 2023）の制約のしくみ（2026-10-06 追記）

詳しくは `decentralised-iterative-planning-2023.md`。約40のエージェントが60ステップかけて町を育てる。各エージェントは「ハード制約を満たす候補地を探す → ランダムに一部を評価 → 評価関数が最も高い所を選ぶ」。

| 層 | 制約 |
| --- | --- |
| 地形 | 高さ、傾き、水、木、既存の構造物の特徴マップ（2次元の配列） |
| ハード制約 | 城壁の内側だけ／外側だけ、水の上だけ、道からの最大距離、傾きの上限、同じ種類との距離、数の上限、他の構造物（道・区画・城壁のマップ）と重ならない |
| ソフト制約 | 傾き・同じ種類との距離の重みづけ、エージェントごとの独自の評価関数（例: 見張り塔は高く、他の塔から遠いほどよい） |
| 時間 | 開始ステップ、実行の間隔、同じエージェントの数（試行の頻度）、「きわめて重要」なら他を取り壊せる |
| 用途 | 架空の経済（雇用・商品・お金）の条件と、近隣の用途による評価で、区画を住宅・商業・工業に分ける（商業は住宅・商業の近く、工業から遠く） |
| 形の生成 | 城壁は区画の凸包を外へ押し出して重みつき A\* でつなぐ。畑は高さごとに膨張させ、等高線に沿わせる |

- 水: 道のエージェントが水の上に橋をかける。「水の上だけ」のエージェントが船や釣りの足場を置く。
- 具体的な数値（傾きの上限、距離の値）は論文に書かれていない。

### 2.8 論文⑤〜⑦: 制約を明示せず、エージェントの行動から配置や道が決まる手法（2026-10-06 追記、軽めに読んだもの）

| 論文 | 配置・道を決めるもの | ハード制約 | 水の扱い |
| --- | --- | --- | --- |
| ⑤ AgentCraft（2021） | 欲求（交流・休息・水・繁殖・建設・木）の優先順位で行動。各マスの「繁栄度」が活動で増え、しきい値を超えると道になる。道は「移動時間を短く・既存の道につなぐ・通れる・重複しない」 | 段差はジャンプの高さ（1ブロック）まで。水・溶岩の上は通れない。開始地点は陸で近くに水（なければ井戸） | 飲み水の資源として歩いて行く。橋はない |
| ⑥ Christiansen & Scirea（2022） | 欲求（空腹・住まい・睡眠・繁殖）を持つ開拓者が、空いている区画に家を建てる。家を持つ者どうしだけが子どもを作る | 幅優先探索で歩ける範囲（段差1ブロック、斜めなし）を求め、25ブロックすべてが歩ける5×5の区画だけを使う | 歩けない所として除くだけ |
| ⑦ Deinböck ほか（2025、要旨のみ） | 家は平らで中心に近い所を優先して確率的に置く。アリが家どうしを歩き、短く平らな道ほどフェロモンが強まって道路網になる | 要旨からは未確認 | 未確認 |

- 論文④が「人が書いた制約と評価関数」で配置を決めるのに対し、⑤〜⑦は「欲求や移動の頻度」から配置や道が生まれる。MineColonies では市民の実際の移動をこの「頻度」として使える【推測】。

## 3. 気づき（方針セッションへの申し送り）

- GDMC の制約の多くは、「建てられるか（平らさ、段差、重なり、水）」と「見た目のまとまり（既存の建物への近さ、種類の相性）」に関するもの。
- 住む人の暮らしに関わる制約は少ない。最も近いのは、2018年2位の「家の適合度＝中心性と道への近さ」。通勤距離や生活サービスへの近さを制約・評価関数にする作品は、今のところ見当たらない。
- 「ハード制約で候補を絞り、ソフト制約（評価関数）で選ぶ」という構造は、MineColonies のハットの配置にもそのまま使える【推測】。例: ハード制約は建物が建設範囲に収まる、通れる、重ならない。ソフト制約は職場と家の距離、食堂や倉庫への近さ。
