### LLM で発言する市民を何人動かせるか(初回の実測、2026-10-30)

条件: 推論は llm-server の llama-server(masbot と共用、GPU 1枚、Gemma 4 26B-A4B Q4_K_M、同時処理4件、MoE の一部を CPU に置く設定)。測定は PR #10 の `chat_capacity_bench.js`(マージ前のブランチ)。発言は40字以内の一言、出力の上限60トークン。ゲームは panama のスーパーフラット、コロニー1つ、自動倍率。

- **実際のゲームでの会話**(市民どうしが直前8行を読んで返す、各市民20秒に1回が目標、各段階2分、ゲーム内チャットへ出力):

| 人数 | 目標に対する発言の割合 | 応答時間 p95 | 判定 |
| --- | --- | --- | --- |
| 8 | 98% | 2.0秒 | 合格 |
| 32 | 88% | 4.1秒 | 不合格(割合が90%未満) |
| 64 | 41% | 4.2秒 | 不合格 |
| 96 | 27% | 4.4秒 | 不合格 |

  - 実際の処理量は毎秒約1.4発言(応答 約2.9秒 × 同時4件)。20秒に1回なら約28人、30秒に1回なら約42人が目安。
  - 540行の発言がゲームに届き、コンソールのエラー(`<--[HERE]`)は0件。
- **推論の速さの測定(throughput モード)は過大だった**: 毎秒約4.5発言と出たが、同じ依頼文を繰り返すため llama-server のプロンプトのキャッシュが効いていた。実際の会話では毎回文章が違い、同時4件のときの生成も遅い(16トークンに約1.9秒)。throughput モードは依頼文を毎回変える必要がある(PR #10 への指摘)。
- **市民の数とサーバーの重さ**(LLM なし、`/spawnCitizen` で増やした家も仕事もない市民、各段階90秒):

| 市民 | 1 tick の処理時間 | 自動倍率 |
| --- | --- | --- |
| 50 | 0.5ms | 40倍 |
| 100 | 0.9ms | 40倍 |
| 200 | 1.7ms | 21倍 |
| 300 | 2.6ms | 13〜14倍 |
| 400 | 3.9ms | 9倍 |

  - 働いていない市民なので、実際のコロニーより軽い。働く市民での測定は別に要る。
- **60秒に1回・60人**(ユーザーがゲームに入って確認): 約8分で497発言、失敗0、応答 p95 3.1秒。会話はチャットで読める速さ(約1行/秒)。ユーザーが確認したので停止した。
