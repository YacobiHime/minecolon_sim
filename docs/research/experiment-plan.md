# 実験計画: 前提を確かめる小さな実験（2026-10-14）

研究としての実験に入る前に、「この前提で進められるか」を確かめるための小さな実験4つの計画です。どれも、配置処理の見直し（実装セッション）を待たずに、今の構成のまま行えます。

- 関係する文書: 方針メモ `docs/research/research-direction-notes.md`（特に5章）、仕様ノート `docs/research/minecolonies-spec-notes.md`、実装セッション `docs/research/implementation-session.md`
- 結果の記録先: `docs/research/experiment-log.md`（最初の実験のときに作る。書き方は下の「記録の形」）

## 全体の進め方

| 順 | 実験 | 決まること | 前提 |
| --- | --- | --- | --- |
| 1 | A: 領土を広げる | 再現できる町の広さ | なし |
| 2 | B: 自分の町を変換する | 現実の地図を使う案（方針メモ5章）を採るかどうか | A の結果で、切り出す範囲を決める |
| いつでも | C: 市民は川を渡るか | 分断を川で表せるか、柵などが必要か | なし |
| いつでも | D: 仮設の小屋（①） | 仮設の小屋を目標レベルまで上げる形（①）のままでいくか、②にするか | なし |

- A → B の順で進める。C と D は独立しているので、空いた時間に進めてよい。
- 配置処理の見直し（実装セッション）は並行して進めてよい。

## 共通のルール

### 実験用のワールド

- **研究室の本番のコロニーとは別のワールドで行う**（本番のワールドのコピーでもよい）。設定を変えたり壊したりしても困らないようにする。
- 実験ごとに新しいワールドを作る。出現地点が平原などの扱いやすい地形から始める（方針メモ8章）。
- 実験ごとに、始める前のワールドをバックアップする（やり直せるように）。
- 研究室の構成（MineColonies 1.20.1-1.1.1231、Structurize 1.20.1-1.0.816、VoyagerBridge、ゲームの速さの自動調整（適応ガバナー）など）は、本番と同じにする。変えた設定は必ず記録する。
- 倍率は自動調整のままでよい。時間を測りたい段階では、倍率を固定にするか、記録した tick 数と倍率から固定の倍率での時間に換算する（方針メモ8章）。

### 記録の形（`docs/research/experiment-log.md` に1回ずつ追記）

```
## 実験 X-n（YYYY-MM-DD）
- 目的: （この回で確かめたいこと）
- 条件: MineColonies の版、変えた設定（ファイル名・項目・値）、ワールド（名前・コピー元）、時間の速さ（自動調整かどうか、倍率の範囲）
- 手順: （実際にやったこと。コマンドや窓口の呼び出しはそのまま書く）
- 結果: （数値、観察したこと、スクリーンショットのファイル名）
- 判断: （下の「判断の基準」に照らしてどうか）
- 分かった仕様: （MineColonies の仕様として残すべきこと → 仕様ノートへの申し送り）
- 次にやること:
```

- 時間は、ゲーム内の日数と、現実の時間（分）の両方を書く。速さは自動調整で変わるので、記録した区間の倍率（例: 最小・最大）も書く（後で換算できるように）。
- 処理の重さは、サーバーの TPS（1秒あたりの処理回数。20が正常）を記録する。Forge のコマンド `/forge tps` で見られる【要確認】。
- 分かった MineColonies の仕様は、仕様把握セッションに渡して仕様ノートに追記してもらう（【実験で確認】の印で）。

## 実験 A: 領土を広げる

### 目的

- `maxColonySize` を上げて広い範囲を確保したとき、**離れた場所の市民や建物が動き続けるか**、**処理が重くなりすぎないか**を確かめ、再現できる町の広さの見当をつける。

### 背景（方針メモ5章の確認結果）

- `maxColonySize` は設定で1〜250チャンクにできる（初期値20）。ただし上げるだけでは領土は広がらず、建物を建てるか、コマンド `/mc colony claim` でまとめて確保する必要がある。
- Minecraft は読み込まれているチャンクしか動かさないので、プレイヤーから離れた市民が止まる可能性がある。

### 手順（案）

1. 実験用ワールドのサーバー設定で `maxColonySize` を上げる（例: 40 → 80 → 160 と段階的に）。設定ファイルの場所と名前を確認して記録する。
2. コロニーの中心から、`/mc colony claim` で広い範囲を確保する。コマンドの正確な書き方は、ゲーム内のコマンドの補完か仕様把握セッションで確認する【要確認】。
3. 中心から 100・300・600 ブロック程度離れた場所に、それぞれ「ビルダーの小屋＋住居＋職場1つ」の小さな地区を作る。
4. 誰かが中心に接続した状態と、無人の状態の両方で、同じ時間（例: ゲーム内で数日）待つ（方針メモ8章）。
5. VoyagerBridge の `/status` などで、各地区の市民の位置・仕事の状態・建設の進み具合を、一定の間隔で記録する。
6. TPS を記録する。
7. VoyagerBridge の強制読み込み（`forceLoadAndClaim` など）があると結果が変わる可能性があるので、どの窓口を使ったかを記録する。

### 記録する項目

- 設定値、確保した半径（チャンク数）
- 地区ごとの、市民が動いていたか（位置が変わるか、仕事が進むか）、建設が進んだか
- TPS の変化

### 判断の基準

| 結果 | 判断 |
| --- | --- |
| 600ブロック離れた地区も動き、TPS がほぼ20を保つ | 町の一地区（数百メートル四方）を1ブロック＝1mで再現できる見込み |
| 接続の有無で結果が違う | 本番は無人で運用するので、無人で動くように VoyagerBridge 側でチャンクを読み込ませる方法を検討する |
| 離れた地区が止まる | チャンクを強制的に読み込む方法（VoyagerBridge 側）を検討する。それでも無理なら、町を縮めて再現する |
| TPS が大きく下がる | 再現する範囲を狭くするか、市民・建物の数を減らす |

## 実験 B: 自分の町を変換する

### 目的

- 自分の町（駅の周り数百メートル）を変換ツールで Minecraft にし、**研究室の環境（1.20.1）で使えるか**、**地形・川・線路・道路がどこまで再現されるか**、**MineColonies の建物がどう収まるか**を確かめる。

### 手順（案）

1. 範囲を決める: 実験 A の結果を見て、駅を中心に数百メートル四方を選ぶ。川や線路による分断が入る範囲にする。
2. Arnis（OpenStreetMap から変換するツール）で変換する。https://arnismc.com/guides/minecraft-world-generator.html
   - 出力される Minecraft のバージョンを確認する。**新しいバージョンのワールドを古いバージョンで開くと壊れることがあるので、必ずコピーで試す。**
   - 1.20.1 で開けない場合の代わり: PLATEAU（国土交通省の3D都市モデル）の変換ツールを試す／変換ツールで新しいバージョンのワールドを作り、地形・川・線路だけを手作業か別の方法で 1.20.1 に移す、など。
3. 研究室の環境（MineColonies 入り）で開き、コロニーを作る。
4. 変換された建物の扱いを試す:
   - MineColonies に対応する施設がない建物（駅、商店など）は、土壁などの障害物として残す（方針メモ5章の決定）。
   - 対応する施設（学校 → 学校、病院 → 病院、役所 → 町役場、住宅 → 住居など）を、元の建物を取り除いて VoyagerBridge で置いてみる。
5. 現実の地図と並べて、どこが再現できていて、どこがずれているかを見る。

### 記録する項目

- 変換した範囲（地図上の範囲。**自宅の位置が分かる情報はプロジェクトの文書に書かない**）
- 使ったツールとそのバージョン、出力された Minecraft のバージョン、1.20.1 で開けたか
- 再現された要素（地形の高さ、川、線路、道路、橋、建物）と、その出来
- MineColonies の建物を置けたか。置けなかった場合の理由（大きさが合わない、傾き、領土など）
- 「現実の施設 → MineColonies の建物」の対応表の下書き

### 判断の基準

| 結果 | 判断 |
| --- | --- |
| 1.20.1 で使え、地形・川・線路が再現され、主な施設を置ける | 現実の地図を使う案を、研究の設定の候補として進める |
| 1.20.1 で使えない | 版の移し方を検討する。手間が大きすぎれば、地図を参考に手で地形を作る方法に切り替える |
| 建物の大きさが合わず、ほとんど置けない | 縮尺を変える（町を縮める）か、置く施設を絞る |

## 実験 C: 市民は川を渡るか

### 目的

- MineColonies の市民が、川を**泳いで渡るか**、**橋まで遠回りするか**を確かめる。分断を川で表せるかが決まる（方針メモ2章）。

### 手順（案）

1. 平らな土地に、まっすぐな川を作る。川の幅を 3・5・10 ブロックの3通りにする（深さも記録する）。
2. 川の片側に住居、反対側に職場（またはレストラン・倉庫など毎日通う施設）を置く。
3. 橋を1本、住居と職場を結ぶ直線から離れた位置に架ける（遠回りが必要な配置）。
4. 市民の移動を、一定の間隔で `/status` などで記録するか、上から観察する。
5. 橋を取り除いた場合も試す（泳いで渡るか、行けなくなるか）。

### 記録する項目

- 川の幅・深さごとの、渡り方（泳ぐ／橋を使う／行けない）
- かかった時間（分かれば）

### 判断の基準

| 結果 | 判断 |
| --- | --- |
| 市民が橋まで遠回りする | 川をそのまま分断として使える |
| 市民が泳いで渡る | 川だけでは分断にならない。柵などで通れない線を作り、すき間を橋や踏切として扱う |
| 幅によって変わる | 分断として使える川の幅の下限を記録して使う |

## 実験 D: 仮設の小屋（①）

### 目的

- 仮設の小屋（ビルダーの小屋）を普通に建て、**目標レベルまで上げるのにかかる時間と資材**を測る。①（目標レベルまで上げる）のままでいくか、②（施設はまずレベル1まで建て、改築は別の工事にする）にするかを決める（方針メモ5章）。
- あわせて、**ビルダーの小屋の改築に、町役場のレベルや研究などの条件があるか**を確かめる。

### 手順（案）

1. 既存のビルダーの小屋から100ブロック以上離れた場所に、建てたい施設を決める（例: レベル3まで上げる施設）。
2. 施設の近くに仮設のビルダーの小屋を置き、市民をビルダーとして割り当てる。
3. 仮設の小屋をレベル1 → 2 → 3 と上げる。各レベルの開始と完了の時刻、使った資材を記録する。
4. 仮設の小屋で、施設本体をレベル3まで建てる。同じく時間と資材を記録する。
5. 改築ができなかった場合は、その理由（ゲーム内のメッセージ）を記録する。

### 記録する項目

- 仮設の小屋の各レベルの建設時間（ゲーム内の日数と現実の分）と資材
- 施設本体の建設時間と資材
- 「仮設の小屋の準備時間 ÷ 施設本体の工事時間」の比
- 改築の条件（あれば）

### 判断の基準

| 結果 | 判断 |
| --- | --- |
| 準備時間が施設本体の工事と同じくらいまで | ①のままでいく（「大きな施設ほど準備工事が長い」という再現とみなす） |
| 準備時間が施設本体の工事よりずっと長い | ②（施設はまずレベル1まで建て、改築は別の工事）を検討する |
| 改築に町役場のレベルなどの条件があり、①が進まない | 条件を満たす手順を考えるか、②に切り替える |

## 実験のあとにすること

- 各実験の「判断」を、方針セッションに持ってきて方針メモに反映する（主軸、現実の地図を使うか、縮尺、分断の表し方、仮設の小屋の扱い）。
- 分かった MineColonies の仕様は、仕様把握セッションで仕様ノートに追記する。
- 実装が必要になったこと（チャンクの強制読み込み、領土をまとめて確保する窓口、柵の設置など）は、実装セッションの作業に加える。
